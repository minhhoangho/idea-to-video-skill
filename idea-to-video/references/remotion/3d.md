# 3D

```bash
npm i @remotion/three three @react-three/fiber
```

```tsx
import { ThreeCanvas, useVideoTexture } from '@remotion/three';

<ThreeCanvas width={width} height={height}>
  <ambientLight intensity={0.6} />
  <directionalLight position={[5, 5, 5]} />
  <mesh rotation={[0, frame * 0.02, 0]}>
    <boxGeometry args={[2, 2, 2]} />
    <meshStandardMaterial color={colors.accent} />
  </mesh>
</ThreeCanvas>
```

`<ThreeCanvas>` rather than react-three-fiber's own `<Canvas>` — it synchronises the render loop with `useCurrentFrame()` instead of running on `requestAnimationFrame`. With the wrong canvas you get a static frame in the output and a working preview in the Studio, which is a miserable way to lose an afternoon.

## Rules

- **Rotation and position come from `frame`.** No `useFrame` deltas, no internal clocks.
- **Lighting decides whether it looks cheap.** A single light gives you the flat, plastic 3D that reads as a placeholder. Key plus fill plus a rim is the minimum.
- **Every asset must be loaded before the frame is captured.** `useGLTF` combined with `delayRender`/`continueRender`, with a `catch` that continues anyway.
- **Render cost is real.** A 3D scene can be an order of magnitude slower per frame than motion graphics. Test with `--frames=0-60` before committing to a full render.

## Whether you need it

For a Reel, usually not. A well-graded 2D composition with real depth cues — parallax, scale, blur — reads as more expensive than a mediocre 3D scene, and renders in a fraction of the time. Reach for 3D when the subject genuinely is an object: a product, a device, a physical mechanism.
